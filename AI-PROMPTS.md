# AI assistance disclosure and representative prompts

AI was used as a coding assistant during the development and refinement of both exercises. It supported implementation questions, debugging, difficult pagination details, browser troubleshooting, visual comparison with the supplied PDFs, print behavior, and documentation refinement.

The developer worked through the assignment requirements, form structures, HTML, CSS layout, JavaScript data handling, dynamic datasets, browser behavior, implementation decisions, and verification. AI assistance did not replace that understanding, and this project is not being presented as entirely AI-generated.

The prompts below are representative examples of the assistance used. They are organized by exercise and are not intended to be a fabricated transcript of every interaction.

## Exercise 1 — Medical and Travel Expense Request

1. > Inspect the current Exercise 1 HTML, CSS, and JavaScript together with the Medical and Travel Expense Request PDF. Identify only genuine visual or pagination mismatches and preserve the existing implementation.

2. > Verify that Prescription Drugs, Over-the-Counter Drugs, medical supplies, parking, mileage, and bus/taxi sections are generated from JavaScript arrays rather than duplicated HTML. Confirm that changing the number of records changes the tables correctly.

3. > Compare the Exercise 1 browser rendering with the supplied PDF for letter-page dimensions, header alignment, table widths, row heights, typography, borders, footer placement, and page numbering. Make only targeted corrections where the PDF shows a mismatch.

4. > Check the sample, extended, and minimal Exercise 1 datasets in the browser and print output. Confirm that the repeated rows, empty states, worker details, claim number, amounts, dates, and page counts update from the selected dataset.

## Exercise 2 — Worker Progress Report

1. > Inspect the current Exercise 2 HTML, CSS, and JavaScript together with the Worker Progress Report PDF and HANDOFF.md. Continue from the current files without rebuilding or redesigning the form.

2. > Compare Exercise 2 page 1 with the reference, especially the narrative boxes, return-to-work section, recovery heading, recovery comments position, footer, and page count. Make only the CSS adjustment required by the PDF geometry.

3. > Verify that the Worker Progress Report fields are data-driven, including worker name, claim number, app ID, submission date, return-to-work status, work status, comments, recovery status, pain score, treatment, medication, exercises, and additional information.

4. > Test the sample, ongoing-recovery, and minimal Exercise 2 datasets. Confirm that changing the selected dataset changes the rendered values, checkbox states, narrative content, and sensible pagination without rewriting the HTML.

5. > Verify native browser printing for Exercise 2. Add or check a Print / Save PDF control using window.print(), hide browser-only controls during printing, and preserve the three-page sample layout.

These examples document AI support for the two exercises while making clear that the final implementation, structure, data decisions, visual comparisons, and verification were handled by the developer.
